# پشتیبان‌گیری و بازیابی

## تهیه پشتیبان
1. تنظیمات → داده‌ها → «پشتیبان‌گیری و بازیابی».
2. گذرواژه (حداقل ۸ نویسه) و تکرار آن را وارد کنید → «ساخت فایل پشتیبان».
3. «ذخیره در Files / iCloud Drive یا اشتراک» → مقصد را خودتان انتخاب کنید (iCloud Drive، Files، AirDrop، …).

برنامه هیچ نسخه‌ای را خودکار به ابر نمی‌فرستد. گذرواژه ذخیره نمی‌شود و بدون آن بازیابی ممکن نیست.

## قالب فایل (`.chortkeh`)

| بایت | محتوا |
|---|---|
| 0–7 | `CHRTKBK1` |
| 8 | نسخه قالب (۱) |
| 9 | KDF: ۱ = PBKDF2-HMAC-SHA256 |
| 10–13 | تعداد تکرار KDF (پیش‌فرض ۶۰۰٬۰۰۰، big-endian) |
| 14–29 | salt تصادفی ۱۶ بایتی |
| 30– | AES-256-GCM (nonce ۱۲ بایت ‖ متن رمز ‖ tag ۱۶ بایت) |

سرآیند ۳۰ بایتی به‌عنوان داده احرازاصالت‌شده (AAD) در GCM استفاده می‌شود؛ هر تغییری در سرآیند یا بدنه رمزگشایی را ناموفق می‌کند. محتوای رمزگشایی‌شده JSON نسخه‌دار (`format`، `schemaVersion`) شامل همه رکوردها، تنظیمات و پیوست‌هاست.

## بازیابی
1. «انتخاب فایل پشتیبان» → گذرواژه → «بررسی فایل».
2. برنامه فایل را کامل رمزگشایی و اعتبارسنجی می‌کند: نسخه، یکتایی شناسه‌ها، مقادیر شمارشی، ارجاع‌های معتبر (حساب، شخص، تعهد، چک، تراکنش) و اینکه هیچ تسویه‌ای بیش از مبلغ نباشد.
3. پیش‌نمایش تعداد رکوردها نمایش داده می‌شود؛ پس از تأیید صریح، همه داده فعلی با پشتیبان در **یک ذخیره اتمیک** جایگزین می‌شود.

## سناریوهای خطا

| وضعیت | نتیجه |
|---|---|
| گذرواژه اشتباه | «گذرواژه اشتباه است یا فایل پشتیبان آسیب دیده است»؛ هیچ تغییری در داده |
| فایل غیرمرتبط/خراب | «فایل پشتیبان معتبر نیست» |
| نسخه جدیدتر از برنامه | «نسخه فایل پشتیبان پشتیبانی نمی‌شود» |
| داده ناسازگار (ارجاع ناموجود، تسویه بیش از مبلغ) | «پشتیبان ناسازگار است: …»؛ پیش از هر حذف رد می‌شود |
| شکست در میانه درج | rollback کامل؛ داده قبلی دست‌نخورده می‌ماند |

این موارد در `Tests/Unit/ReminderAndCryptoTests.swift` (BackupCryptoTests) و `Tests/Integration/LedgerServiceIntegrationTests.swift` (BackupRestoreIntegrationTests) آزمون شده‌اند.

## حذف همه اطلاعات
تنظیمات → «حذف همه اطلاعات» با دو مرحله تأیید. پیشنهاد می‌شود پیش از آن پشتیبان بگیرید.
